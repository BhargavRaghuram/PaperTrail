PaperTrail reads a car's papers and catches what a human skim misses.

A used-car buyer in India photographs the RC, service book and insurance. PaperTrail rebuilds the car's timeline, cross-checks it against live web data the seller can't fake, and hands over the exact questions to ask before paying ₹3–5 lakh.

The problem — one named user, one specific failure

India has no Carfax.

The data that answers "is this car what the seller says" already exists — RC book, service booklet, insurance papers — but it's on paper, scattered across three documents that were never meant to be cross-checked. Nobody reconciles them by hand because it's tedious. Agencies charge ₹2,000 to do it manually.

PaperTrail does the ₹2,000 agency check live for under ₹100 — plus the future-cost warning the agency never gives you.

How it's judged — the four axes, answered honestly

The scorecard

Every submission is judged on new capability, whether it works live, keep-or-share, and a two-minute demo. Here is exactly where PaperTrail stands on each.

1 · New capability

The core bet

A scanner app OCRs a document. PaperTrail reasons across a reconstructed timeline — and against the live web. Neither is possible without a frontier model doing genuine judgment under messy, incomplete, real-world data.

  • Catches a contradiction that lives between three documents, not in any one — "June 2021 says 34,200 km, Jan 2023 says 31,800 km." No OCR finds that.
  • Cross-checks the paper against ground truth it scrapes live (market price, and for a real registration, the public record and challans) — "the papers say 2 owners, the record shows 3." Impossible to reproduce by uploading a photo to a chatbot.
  • Reads real handwritten Indian service booklets with Claude Opus vision into strict JSON.

2 · It works — live

Proven

Not a mockup. The engine is a verified port of a reference rules engine and passes an automated oracle; the web calls are real HTTP 200s consuming real credits.

  • 50/50 automated tests green, including all 13 reconciliation scenarios matched exactly to ground truth.
  • Live Claude Opus vision extraction confirmed on real document images.
  • Live Anakin web scraping confirmed — real Cars24 & Spinny listings, credits visibly consumed (see proof below).
  • Production build passes; deployed to a hosted link.

3 · Keep or share

Strongest axis

"I'm buying a used car this weekend — send this to my cousin." A real ₹3–5 lakh decision, made by millions of people a year, with no existing tool. You'd use it next week and forward it to a friend mid-purchase.

4 · Clarity of demo

Under 60 seconds

Upload three photos → a timeline draws in → the odometer drops on screen (physically impossible, instantly legible) → sourced flags → a printable question sheet. The catch is visual; no explanation needed.

What actually happens when you press "Check car"

The pipeline

Two model touch-points, one deterministic core, one live-web moat. The model is load-bearing exactly where judgment is needed — nowhere else.

01

ExtractClaude Opus vision

Each document photo → strict JSON. Unreadable fields are marked low-confidence and excluded, never guessed.

02

Build the timelineDeterministic code

Registration, services, insurance and challans merged into one chronological sequence. No model — it must be exact.

03

Reconcile7 verified rules

Odometer regression, implausible jumps, service gaps, insurance lapses, ownership & identity mismatch, missing history — each a sourced flag with severity.

04

Cross-check the live webAnakin API

Market price from Cars24 / Spinny / CarDekho; for a real registration, public-record owner count and traffic challans — the data a seller can't edit.

05

Forecast hidden costsParts catalog

Big-ticket parts near end of life for the car's age & mileage — the alternator that'll cost ₹12k next year.

06

Questions for the sellerTemplate map

Every flag becomes one printable, pointed question — the artifact the buyer holds at the sale.

Three independent ways a judge can verify it live:

A

Server log

Every call prints [anakin] LIVE /search <- 200 in the terminal. Missing key would print SKIP; a failure prints HTTP 4xx (fallback).

B

The UI badge

The "Similar cars on the market" section shows a green ● Live via Anakin pill, which renders only when market.source === "live".

C

Credits on the dashboard

Anakin bills one credit per call. The balance dropped 5,300 → 5,275 across a demo session — 25 real calls. A mock consumes zero.

Why it's not in the browser Network tab: the Anakin call is server-to-server (our API route → api.anakin.io), so the key never touches the client. That's correct architecture — and the reason it's invisible to the browser but visible in the server log.
